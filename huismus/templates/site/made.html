{% translate "Gemaakt" %}

{% translate "Zo wordt Huismus gemaakt" %}

{% translate "Bij Huismus staat kwaliteit voorop: het gaat om je boekhouding. AI schrijft veel van de code, de maker beslist en kijkt mee, en bij elke wijziging wordt nagekeken of je facturen en bedragen blijven kloppen." %}

{% translate "AI maakt veel, de maker beslist" %}

{% translate "De maker bepaalt wat er gebouwd wordt en in welke volgorde. De lijst met werk staat openbaar bij de code. AI schrijft daarna het plan, de code, de tests en de teksten." %}

{% translate "Een nieuw scherm, of een taak die anders gaat lopen, bekijkt de maker zelf voordat het in Huismus komt. Ook over geld, over tekst over wet of belasting zonder bron, en over alles wat bestaande gegevens wijzigt, beslist de maker en niet de AI." %}

{% translate "De code zelf leest de maker niet regel voor regel na. Dat doen de tests en de reviewers hieronder. De maker doet de eigen administratie in Huismus en probeert een nieuwe versie daar eerst." %}

{% translate "Vaste regels, in gewone tekst" %}

{% translate "De regels waar Huismus zich aan houdt, staan in gewone tekst bij de code: bedragen in centen, uitgegeven ligt vast, nummers zonder gaten, één plek voor de totalen. Tijdens het bouwen kijken AI-reviewers met elk één opdracht naar een wijziging: houdt hij zich aan die regels, doet hij wat er was afgesproken, en is de code uit te leggen." %}

{% translate "Het werk gaat in kleine stappen: één onderwerp per wijziging, met eerst een plan. Voor alles wat met facturen rekent, komen de tests vóór de code." %}

{% translate "Wat Huismus over belasting zegt, komt uit een officiële bron, met de link en de datum erbij. Is er geen bron, dan zegt Huismus het niet." %}

{% translate "Alle tests, bij elke wijziging" %}

{% blocktranslate %}Huismus heeft meer dan {{ tests_at_least }} tests. Een test is een stukje code dat Huismus iets laat doen en nakijkt of de uitkomst klopt: een factuur uitgeven, een totaal uitrekenen, een export inlezen.{% endblocktranslate %}

{% translate "Bij elke wijziging draaien ze allemaal op GitHub, de plek waar de code van Huismus openbaar staat: eerst op de wijziging zelf, daarna op het geheel. Eén commando zegt ja of nee." %}

{% translate "Datzelfde commando kijkt ook of de database bij de code past, en of er geen bestanden van een echte administratie tussen de code staan." %}

{% translate "Een uitgegeven factuur ligt vast" %}

{% translate "Na het uitgeven kun je een factuur of creditnota niet meer wijzigen of verwijderen. Een fout herstel je met een creditnota." %}

{% translate "Twee plekken bewaken dat. De code van Huismus weigert zo’n wijziging, en de database weigert hem zelf ook: voor het document, voor de regels en voor de btw per tarief. Zit er een fout in de code, dan houdt de database de wijziging alsnog tegen." %}

{% translate "Er is één uitzondering, en die kies je zelf: met Toch bewerken zet je een factuur terug naar concept, met hetzelfde nummer. Dat kan niet meer als er een creditnota voor die factuur is uitgegeven." %}

{% translate "Nummers zonder gaten" %}

{% translate "Een factuur krijgt zijn nummer pas bij het uitgeven, in dezelfde stap waarin hij wordt vastgelegd. Mislukt het uitgeven, dan is er ook geen nummer verbruikt." %}

{% translate "Een test vraagt twintig nummers tegelijk aan en kijkt of het precies 1 tot en met 20 worden: geen gat en geen dubbel nummer." %}

{% translate "Bedragen in hele centen" %}

{% translate "Huismus slaat elk bedrag op in hele centen, zodat er bij het rekenen geen cent verdwijnt. Eén stuk code rekent de totalen uit, voor het scherm en de pdf. De import rekent er je oude facturen mee na." %}

{% translate "Tests met willekeurige facturen kijken of het subtotaal altijd de som van de regels is, en het totaal altijd het subtotaal plus de btw." %}

{% translate "De import rekent elk totaal na" %}

{% translate "Een import begint met een proefdraai: je ziet wat er zou gebeuren, en er is nog niets opgeslagen. Huismus rekent van elke factuur het totaal opnieuw uit en vergelijkt het met het totaal uit je oude pakket, tot op de cent. Wijkt er een af, dan zie je welke en hoeveel." %}

{% translate "Lees je dezelfde export twee keer in, dan verandert er de tweede keer niets. Ook dat kijkt een test na." %}

{% translate "In een echte browser" %}

{% translate "Een deel van de tests bedient Huismus in een echte browser, zoals jij dat doet: klikken, typen, een factuur uitgeven. Ze openen elke pagina in het Nederlands en het Engels, op drie schermbreedtes van telefoon tot breed scherm, en lopen de app door met negen jaar verzonnen administratie." %}

{% translate "Bij elke wijziging gebeurt dat in Chromium, de motor van Chrome en Edge. Verandert er iets aan wat je ziet, dan daarna ook in de motoren van Safari en Firefox." %}

{% translate "Voor elke nieuwe versie" %}

{% translate "Een nieuwe versie komt pas online als twee controles slagen: er zit geen bekend lek in de pakketten waar Huismus op bouwt, en de veiligheidscontrole van Django, het raamwerk onder Huismus, geeft geen waarschuwing." %}

{% translate "Vóór die controles loopt een aparte AI-reviewer alles na wat sinds de vorige versie is veranderd: wachtwoorden en sleutels, verbindingen naar buiten, ingangen zonder inloggen en alles wat je inleest. Een bevinding met ernst hoog of middel houdt de versie tegen tot hij is opgelost. Een lichte komt op de lijst met werk. Dit is een afspraak die bij de code staat, geen automatische controle." %}

{% translate "Wat een test niet vangt" %}

{% translate "Een test vangt alleen wat iemand heeft bedacht. Sommige fouten vindt pas iemand die Huismus gebruikt. Voor zo’n fout komt er eerst een test die hem laat zien, dan de oplossing, en waar het kan een controle die elke fout van die soort vangt." %}

{% blocktranslate with bugs=sources.bugs %}De lijst van die fouten staat bij de code, ook de soorten waar nog geen controle voor is. Vind je zelf een fout, meld hem dan.{% endblocktranslate %}
